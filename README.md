# Stardew SOOP Bridge Central — 관리자/누락 보상 기반

이 패키지는 Windows PC에서 실행하는 중앙 웹 서버의 **관리자 전용 웹페이지, 운영진 역할 분리, 영구 보상 작업 대기열, 게임 PC의 아웃바운드 폴링 API**를 제공합니다. Node.js 20 이상이 필요합니다.

> **현재 구현 범위를 정확히 확인하세요.** 관리자 인증/권한/대기열/게임 연결 프로토콜은 구현되어 있습니다. 다만 기존 SOOP 브라우저 SDK 인증 흐름은 중앙 서버의 스트리머 인증·이벤트 전달 API와 아직 완전히 통합되어 있지 않습니다. 실제 방송에서 후원이 자동 접수되는 완성품이라고 간주하면 안 됩니다. SOOP SDK 이벤트 어댑터는 `/api/ingest/donation`에 서버 간 인증으로 이벤트를 전달해야 하며, 이 비밀 토큰을 브라우저 JavaScript에 넣으면 안 됩니다. 또한 SMAPI 코드는 기존 모드 프로젝트의 실제 대상 프레임워크/참조로 빌드 및 게임 테스트가 필요합니다.

## 포함 기능

- `/admin` 관리자 페이지
- 최고 관리자와 운영진 계정 분리: 최고 관리자만 운영진 추가/비활성화 및 방송 연결 등록 가능
- 관리자/운영진 로그인, scrypt 비밀번호 해시, HttpOnly/SameSite 세션 쿠키, CSRF 토큰, 로그인 시도 제한
- SQLite 대신 의존성을 줄인 JSON 영구 저장소(`data/db.json`, 임시 파일 후 원자적 rename)
- 수동 보상 작업, 상태/시도 횟수/오류/감사 로그, 누락 작업 재시도 또는 확인 필요 표시
- 방송별 게임 연결 토큰: 생성 시 한 번만 노출되고 서버에는 SHA-256 해시만 저장
- SMAPI 모드에서 중앙 서버로 아웃바운드 폴링: 스트리머 게임 PC의 포트를 인터넷에 공개할 필요 없음
- 후원 ingest API의 이벤트 중복 체크와 보상 작업 생성

## 1. 설치 (Windows PowerShell)

프로젝트 압축을 풀고 해당 폴더에서 실행하세요.

```powershell
node --version
npm.cmd install
Copy-Item .env.example .env
notepad .env
```

`.env`에서 다음 항목을 반드시 바꿉니다.

- `SESSION_SECRET`: 32바이트 이상 무작위 비밀값
- `ADMIN_USERNAME`: 최고 관리자 아이디
- `ADMIN_PASSWORD`: 다른 곳에서 쓰지 않는 강력한 비밀번호
- `DONATION_INGEST_TOKEN`: SOOP 이벤트를 서버로 전달하는 신뢰된 어댑터만 아는 별도 토큰
- `HOST=127.0.0.1`은 로컬에서 TLS 프록시(Caddy)를 거쳐 접속할 기본값입니다.

PowerShell에서 무작위 값 만들기:

```powershell
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

서로 다른 값을 3개 생성해 `SESSION_SECRET`, `ADMIN_PASSWORD`(값의 형식은 비밀번호 정책을 충족하는 값), `DONATION_INGEST_TOKEN`에 설정하세요. 실제 비밀번호는 생성된 무작위 문자열을 그대로 사용해도 됩니다. `.env`를 공유하거나 Git에 올리지 마세요.

실행:

```powershell
npm.cmd start
```

로컬 확인:

- `http://127.0.0.1:3000/` — 안내 화면
- `http://127.0.0.1:3000/admin` — 관리자 로그인
- `http://127.0.0.1:3000/health` — 상태 확인

최초 실행 시 `.env`의 최고 관리자 계정이 생성됩니다. 계정이 이미 생성된 뒤 `.env`의 `ADMIN_PASSWORD`를 바꿔도 기존 계정의 비밀번호는 자동 변경되지 않습니다. 이 경우 계정 복구 절차를 별도로 수행해야 합니다.

## 2. 도메인/HTTPS 공개

도메인 DNS를 집의 공인 IP에 연결하고 공유기에서 TCP 80/443을 해당 PC의 Caddy로 전달해야 합니다. Node 서버 포트 3000은 외부에 직접 포워딩하지 마세요. Caddy를 설치한 뒤 `deploy/Caddyfile.example`의 도메인을 실제 도메인으로 바꾸고 Caddy에 적용합니다. DNS/포트 포워딩/방화벽/CGNAT 상황에 따라 외부 접속이 되지 않을 수 있습니다.

Caddy를 통한 HTTPS 종료 환경에서만 `.env`의 `TRUST_PROXY=true`로 설정하세요. 이 설정을 신뢰되지 않는 프록시 환경에서 켜면 안 됩니다. 도메인만 만든다고 자동으로 HTTPS나 외부 접속이 설정되는 것은 아닙니다.

## 3. 관리자 페이지 사용

1. `/admin`에 최고 관리자 계정으로 로그인합니다.
2. `게임 연결 등록`에서 스트리머 표시 이름과 SOOP 방송 ID(bjId)를 등록합니다.
3. 생성된 `AgentToken`은 한 번만 표시됩니다. 안전한 경로로 해당 스트리머에게 전달하고 게임 모드의 `config.json`에 설정합니다.
4. 스트리머 게임 모드가 연결되면 마지막 접속 시각이 표시됩니다.
5. `수동 보상 지급`에서 방송, 상자/몬스터, 수량, 사유를 선택해 작업을 등록합니다.
6. 게임이 `/api/agent/poll`로 작업을 가져오고 SMAPI가 로컬 저장 상태에 반영한 뒤 `/api/agent/ack`로 결과를 보고합니다.
7. `RETRY` 또는 `REVIEW` 작업은 지급 여부를 확인한 뒤에만 재시도합니다. 이미 지급됐을 가능성이 있으면 바로 재시도하지 말고 먼저 게임 로그와 우편함을 확인하세요.

운영진은 보상 지급과 누락 보상 관리를 할 수 있지만 방송 연결 등록과 운영진 계정 관리는 할 수 없습니다. 최고 관리자만 운영진을 추가하거나 비활성화할 수 있습니다.

## 4. SMAPI 게임 연결

`smapi-mod-source/ModEntry.cs`는 기존 소스에 중앙 폴링을 추가한 버전입니다. 이 파일은 단독 실행 파일이나 DLL이 아닙니다. 기존 SMAPI 모드 프로젝트의 `ModEntry.cs`를 백업한 뒤 이 파일과 병합하고, 기존 모드 프로젝트에서 빌드해야 합니다.

모드 `config.json`에 다음 항목을 직접 추가해야 합니다. 기존 설정 파일은 백업한 뒤 편집하고, JSON 쉼표/따옴표가 올바른지 확인하세요.

```json
{
  "CentralServerUrl": "https://실제-도메인",
  "AgentToken": "관리자 페이지에서 발급한 방송별 토큰"
}
```

`CentralServerUrl`에는 끝의 `/`를 생략합니다. 이 연결은 게임 PC에서 중앙 서버로 나가는 HTTPS 요청이므로 스트리머 공유기에서 게임 모드의 HTTP 포트를 외부 공개할 필요가 없습니다.

**중요:** 이 버전의 중앙 작업은 SMAPI가 승인된 `links.json`의 `SoopId`, `FarmerId`, `AdminApproved`, `StreamerVerified` 매핑을 찾아야 실제 로컬 보상 대기열에 등록됩니다. 중앙 방송 등록과 로컬 게임 링크 승인은 별개의 단계입니다. 매핑이 없으면 작업이 `REVIEW`로 이동합니다. 실제 운영 전 각 방송에서 링크 설정을 확인하세요.

중앙 서버 `COMPLETED`는 SMAPI가 작업을 중복 방지 저장소에 기록하고 로컬 보상 대기열에 반영했다는 의미입니다. 게임에서 상자를 실제로 열었거나 몬스터가 화면에 나타났다는 것을 의미하지는 않습니다. 상자는 게임 우편함에 등록되며, 플레이어가 우편함에서 수령해야 합니다. 로컬 SMAPI 상태(`state.json`)도 백업해야 합니다.

## 5. 후원 자동 수신 API

신뢰된 서버 측 SOOP 어댑터는 다음 API에 요청합니다.

```http
POST /api/ingest/donation
Content-Type: application/json
X-Donation-Token: <DONATION_INGEST_TOKEN>

{"eventId":"고유한-원본-이벤트-ID","soopId":"방송ID","balloons":100}
```

현재 API는 동일 `soopId + eventId` 중복을 무시하고 후원 기록 및 보상 작업을 만듭니다. SDK가 안정적인 원본 이벤트 ID를 제공하지 않으면 임의 UUID만으로는 재연결 중 중복을 완벽히 막을 수 없습니다. 실제 SOOP SDK 이벤트의 필드/ID와 공식 인증 흐름을 검증해 어댑터를 연결해야 합니다. `DONATION_INGEST_TOKEN`을 `public/*.html` 또는 브라우저 스크립트에 포함하지 마세요.

현재 API 보상 계산은 프로덕션 기준으로 구현되어 있습니다: 33개 이상은 몬스터 1마리, 100~999개는 100개당 상자 1개, 정확히 1000개는 상자 11개. 1000개 초과는 현재 규칙상 상자를 지급하지 않습니다. 프로덕션 규칙 변경 시 서버와 SMAPI 모드의 계산 규칙을 함께 변경하세요. 사용자가 확정한 규칙이 1000개 초과에서 다르다면 실제 방송 전에 계산 규칙을 수정하고 테스트하세요.

## 6. 누락/복구 정책

- 후원 기록을 먼저 영구 저장하고 보상 작업을 별도 생성합니다.
- 동일 이벤트 ID는 재수신 시 중복 작업을 생성하지 않습니다.
- 게임이 오프라인이면 작업은 대기합니다.
- 게임이 작업을 가져간 뒤 2분 동안 확인 응답이 없으면 `RETRY`로 바뀝니다. 이 경우 실제로 지급됐는지 불명확할 수 있으므로 자동 재지급하지 않습니다.
- 운영자는 게임의 SMAPI 로그와 `state.json`을 확인하고 안전한 경우 재시도합니다. 지급 여부가 불확실하면 `확인 필요`로 표시합니다.
- `/api/ingest/donation`에 도달하기 전 SOOP 이벤트가 유실되면 이 서버는 그 후원을 알 수 없습니다. SOOP 기록/방송 기록을 대조해 수동 보정해야 합니다.

## 7. 빌드/테스트 체크리스트

- [ ] `npm.cmd install` 성공
- [ ] `.env` 필수 비밀값 설정 및 `/admin` 로그인
- [ ] 일반 스트리머 브라우저에서 `/admin`은 로그인 없이 관리자 데이터를 반환하지 않음
- [ ] 운영진 계정으로 방송 등록/운영진 관리 불가
- [ ] 게임 토큰 오입력 시 401, 올바른 토큰으로 폴링 성공
- [ ] 게임 연결 종료 후 작업이 대기 상태로 유지됨
- [ ] 모드의 `links.json`이 승인된 방송 ID와 FarmerId를 가리킴
- [ ] 보상 작업 중 게임 종료/재시작 후 중복 지급 여부 확인
- [ ] 상자 우편과 몬스터 소환을 실제 게임에서 확인
- [ ] 테스트 방송에서 중복 후원 이벤트, 타임아웃, 네트워크 단절을 검증
- [ ] HTTPS 도메인에서 로그인 쿠키가 Secure로 설정됨

이 패키지는 관리 서버의 실용적인 기반을 제공하지만, 위 테스트를 통과하기 전까지는 운영용으로 완전히 검증된 상태가 아닙니다.
